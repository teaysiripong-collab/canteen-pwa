# MEKTEC Canteen Menu & Purchasing System

ระบบบริหารเมนูอาหาร สูตรอาหาร วัตถุดิบ สต๊อก ต้นทุน และใบสั่งซื้อของโรงอาหารบริษัท MEKTEC
สร้างด้วย **Google Apps Script + Google Sheets** รองรับคอมพิวเตอร์ โทรศัพท์ และแท็บเล็ต
รองรับผู้ใช้งานพร้อมกันมากกว่า 100 คน

> **สถานะ:** ระบบเต็มรูปแบบ (v3.0.0) — ครบทุกโมดูลตามข้อกำหนด: Dashboard, วางแผนเมนูรายสัปดาห์ (บันทึก
> อัตโนมัติ), สูตรอาหารมาตรฐาน, ค่ามาตรฐาน & วัตถุดิบ, Vendor Master (พร้อมรายการวัตถุดิบที่จำหน่าย),
> ระบบสต๊อก (FEFO), **ใบสั่งซื้อ 1 ใบต่อวัน จัดกลุ่มตามช่วงเวลา → เมนู ตรงกับเอกสารจริงของ MEKTEC
> พร้อมสรุปยอดตาม Vendor อัตโนมัติ** (แสดงรายละเอียดสูตรคำนวณครบทุกขั้นตอน + Preview ก่อนสร้าง PDF +
> โลโก้ MEKTEC), คู่มือครัวประจำวัน + QR Code, ใบประกาศเมนู (มีโลโก้), รายงาน 11 ประเภท (รวมต้นทุน
> รายสัปดาห์/รายเดือน และประวัติราคาจริง) + Export PDF/Excel/CSV, ระบบผู้ใช้งาน 4 สิทธิ์, Pagination
> และปุ่มย้อนกลับทุกหน้าจอ
>
> **v3.0.0 ปรับโครงสร้างใบสั่งซื้อใหม่ทั้งหมด** ให้ตรงกับเอกสารกระดาษจริงที่ใช้งานอยู่ (จากเดิมที่ระบบ
> แยกใบสั่งซื้อตาม Vendor ซึ่งไม่ตรงกับการทำงานจริง) — ดูรายละเอียดที่หัวข้อ 10

## 1. สถาปัตยกรรมระบบโดยย่อ

```
ผู้ใช้งาน (มือถือ/แท็บเล็ต/คอมพิวเตอร์)
        │  HTTPS
        ▼
Google Apps Script Web App
  ├─ Code.gs   : Server-side logic (API endpoints, business rules, auth, PDF export)
  └─ Index.html: Single-page client (HTML+CSS+JS, เรียก Code.gs ผ่าน google.script.run)
        │
        ├──▶ Google Sheets "MEKTEC Canteen Database" (ฐานข้อมูลหลัก 20 ชีต)
        └──▶ Google Drive โฟลเดอร์ "MEKTEC Canteen PDFs" (ไฟล์ PDF ใบสั่งซื้อ/รายงาน)
```

- **ไม่มี framework ภายนอก** ทุกอย่างอยู่ใน 2 ไฟล์หลัก (`Code.gs`, `Index.html`) ตามข้อกำหนด
- **การยืนยันตัวตน**: ใช้ Username + PIN ของระบบเอง (ไม่ใช่ Google Login) เก็บรหัสแบบ SHA-256 hash
  session token เก็บใน `CacheService` อายุ 6 ชั่วโมง
- **การป้องกันข้อมูลชนกัน**: ทุกจุดที่เขียนข้อมูลสำคัญใช้ `LockService.getScriptLock()`
- **เขตเวลา**: ทุกวันที่/เวลาที่ระบบสร้างอ้างอิง `Asia/Bangkok`
- **Audit Log**: ทุกการเพิ่ม/แก้ไข/ลบข้อมูลสำคัญถูกบันทึกในชีต `AuditLogs`
- **การสร้าง PDF/Excel**: ใช้เทคนิคสร้างชีตชั่วคราวในสเปรดชีตฐานข้อมูล จัดรูปแบบ แล้ว Export ผ่าน
  Google Sheets export URL (`UrlFetchApp` + OAuth token) จากนั้นลบชีตชั่วคราวทิ้งทันที และบันทึกไฟล์
  PDF ที่ได้ลงโฟลเดอร์ Google Drive "MEKTEC Canteen PDFs"
- **QR Code**: ใช้บริการสาธารณะ `api.qrserver.com` สร้างภาพ QR จากลิงก์ลึก (deep link) ของแต่ละสูตรอาหาร
  (ดูข้อ 7 รายการที่ควรปรับก่อนใช้งานจริง หากองค์กรมีนโยบายไม่ใช้บริการภายนอก)

## 2. โครงสร้าง Google Sheets

`setupSystem()` จะสร้างสเปรดชีตชื่อ **"MEKTEC Canteen Database"** พร้อมชีตทั้งหมดต่อไปนี้โดยอัตโนมัติ:

| ชีต | ใช้เก็บอะไร |
|---|---|
| Settings | ค่าตั้งค่าระบบ (ชื่อบริษัท, เวอร์ชัน ฯลฯ) |
| Users | ผู้ใช้งาน, สิทธิ์, PIN (hash) |
| Vendors | ข้อมูลผู้ขาย/ซัพพลายเออร์ |
| Ingredients | วัตถุดิบมาตรฐาน ราคา ค่าเผื่อ หน่วยปัด Safety Stock (ตั้งค่าต่างกันได้ต่อรายการ) |
| Recipes | สูตรอาหารมาตรฐาน (หัวเมนู) |
| RecipeItems | วัตถุดิบในแต่ละสูตร |
| WeeklyMenus | สัปดาห์ของแผนเมนู |
| MenuItems | เมนูรายวัน/ช่วงเวลาที่วางแผนไว้จริง |
| MenuTemplates / MenuTemplateItems | Template เมนูสำหรับเรียกใช้ซ้ำ |
| InventoryLots | ล็อตวัตถุดิบคงเหลือ (รับเข้า/วันหมดอายุ/คงเหลือ) |
| StockTransactions | ประวัติรับเข้า/เบิก/โอน/ปรับยอด/ตรวจนับ/ของเสีย/หมดอายุ/คืน Vendor |
| PurchaseOrders / PurchaseOrderItems | ใบสั่งซื้อและรายการ |
| PurchaseOrderItemHistory | ประวัติการแก้ไขรายการในใบสั่งซื้อ (ค่าเดิม/ค่าใหม่/ผู้แก้ไข/เหตุผล) |
| StandardSettings | ค่ามาตรฐานเผื่อ/ปัด/Safety Stock แยกตามหมวดหมู่ |
| Locations | สถานที่ให้บริการ (ตึก 1, ตึก 16) |
| TimeSlots | ช่วงเวลาบริการทั้ง 6 ช่วง |
| AuditLogs | ประวัติการแก้ไขข้อมูลทั้งหมด |

ทุกชีตมีแถวหัวคอลัมน์ (Header) ตายตัวตาม `SHEET_SCHEMA` ใน `Code.gs` — ห้ามแก้ชื่อคอลัมน์ในชีตโดยตรง
เพราะระบบอ่าน/เขียนโดยอ้างอิงชื่อคอลัมน์เหล่านี้

## 3. วิธีติดตั้งทีละขั้นตอน

1. ไปที่ [script.google.com](https://script.google.com) แล้วกด **โปรเจกต์ใหม่ (New project)**
2. ตั้งชื่อโปรเจกต์เป็น `MEKTEC Canteen System`
3. ลบโค้ดเริ่มต้นในไฟล์ `Code.gs` ทั้งหมด แล้ววางเนื้อหาจากไฟล์ `Code.gs` ในโปรเจกต์นี้ทั้งหมด
4. เพิ่มไฟล์ HTML ใหม่ (คลิก **+** ข้าง Files → HTML) ตั้งชื่อว่า `Index` (ต้องชื่อ `Index` เป๊ะ ๆ)
   แล้ววางเนื้อหาจากไฟล์ `Index.html` ในโปรเจกต์นี้ทั้งหมด
5. เปิดไฟล์ตั้งค่าโปรเจกต์ (ไอคอนเฟือง → Project Settings → Show "appsscript.json" manifest file
   in editor) แล้ววางเนื้อหาจาก `appsscript.json` ทับของเดิม (หรือกำหนด Time zone เป็น
   `Asia/Bangkok` ผ่านเมนู Project Settings ก็ได้)
6. บันทึกโปรเจกต์ทั้งหมด (Ctrl+S / Cmd+S)
7. เลือกฟังก์ชัน **`setupSystem`** จาก dropdown ด้านบน แล้วกด **Run (▶)**
   - ครั้งแรกที่รัน ระบบจะขอสิทธิ์ (Authorize) — กด **Review permissions** เลือกบัญชี Google
     ของคุณ แล้วกด **Advanced → Go to MEKTEC Canteen System (unsafe)** → **Allow**
     (ข้อความ "unsafe" เกิดเพราะสคริปต์ยังไม่ได้ตรวจสอบโดย Google ซึ่งปกติสำหรับสคริปต์ภายในองค์กร)
   - Apps Script จะขอสิทธิ์เพิ่มเติมสำหรับ Google Drive และการเชื่อมต่อภายนอก (ใช้สำหรับสร้าง/บันทึก
     PDF ใบสั่งซื้อและรายงาน) — กด Allow เช่นกัน
   - เมื่อรันสำเร็จจะเห็นข้อความ "ติดตั้งระบบสำเร็จ..." ใน Execution log
8. ตรวจสอบไฟล์ Google Sheets ที่ถูกสร้างขึ้นใหม่ชื่อ **"MEKTEC Canteen Database"**
   ในไดรฟ์ของคุณ — ควรมีชีตครบ 20 ชีต พร้อมข้อมูลตัวอย่าง

## 4. วิธี Deploy เป็น Google Web App

1. ในตัวแก้ไข Apps Script กด **Deploy → New deployment**
2. คลิกไอคอนเฟืองข้าง "Select type" แล้วเลือก **Web app**
3. ตั้งค่า:
   - **Description**: `MEKTEC Canteen v3.0.0`
   - **Execute as**: `Me` (บัญชีของคุณ — เพื่อให้สคริปต์เข้าถึง Sheets/Drive ได้เสมอ)
   - **Who has access**: เลือกตามนโยบายบริษัท
     - `Anyone` — ใช้งานได้จากลิงก์โดยไม่ต้องล็อกอิน Google (ระบบมีหน้า Login ของตัวเองอยู่แล้ว)
     - `Anyone within [องค์กรของคุณ]` — ปลอดภัยกว่า หากใช้ Google Workspace ขององค์กร (**แนะนำ**)
4. กด **Deploy** แล้วกด **Authorize access** อีกครั้งหากมีการขอสิทธิ์เพิ่ม
5. คัดลอก **Web app URL** ที่ได้ แล้วแจกจ่ายให้พนักงานใช้งาน (บันทึกเป็น Bookmark/Add to Home
   Screen บนมือถือได้ทันที) — ลิงก์นี้ยังใช้เป็นฐานของ QR Code ในหน้าคู่มือครัวประจำวันด้วย
6. เมื่อแก้ไขโค้ดในอนาคต ให้กด **Deploy → Manage deployments → แก้ไข (ไอคอนดินสอ) →
   New version** เพื่ออัปเดต URL เดิมโดยไม่ต้องแจก URL ใหม่

## 5. วิธีทดสอบระบบ

1. เปิด Web app URL จากขั้นตอนที่ 4 แล้วเข้าสู่ระบบด้วยบัญชีตัวอย่าง (ดูหัวข้อที่ 6)
2. **แดชบอร์ด**: ตรวจสอบว่ามีตัวเลขและกราฟแสดงผลจากสัปดาห์ตัวอย่างที่ seed ไว้
3. **วางแผนเมนูรายสัปดาห์**: เพิ่ม/แก้ไข/ลบเมนู, ทดลอง "คัดลอกจากวันก่อนหน้า",
   "คัดลอกไปสัปดาห์ถัดไป", "บันทึกเป็น Template" และ "ใช้ Template นี้"
4. **สูตรอาหารมาตรฐาน**: เปิดดูเมนูตัวอย่าง เช่น "ผัดกะเพราหมู" แล้วลองใช้ตัวคำนวณ
   "คำนวณวัตถุดิบตามจำนวนที่ต้องการผลิต" — ใส่ 70 แล้วตรวจสอบว่าหมูบดคำนวณได้ 8.4 กก.
   (สูตรมาตรฐาน 12 กก. ต่อ 100 ที่ × 70 ÷ 100)
5. **ค่ามาตรฐาน & วัตถุดิบ**: แก้ไขราคา/ค่าเผื่อของวัตถุดิบ แล้วกลับไปดูว่าต้นทุนสูตรอาหารเปลี่ยนตาม
6. **สต๊อก**: ทดลอง "รับเข้า" วัตถุดิบ 1 ล็อต แล้ว "เบิกใช้" จำนวนหนึ่ง — ตรวจสอบว่าระบบตัดจากล็อตที่
   ใกล้หมดอายุก่อน (FEFO) ในแท็บ "ประวัติ"
7. **ใบสั่งซื้อ**: เลือกวันที่ (แนะนำวันที่ตรงกับสัปดาห์ตัวอย่าง) กด "สร้าง/รีเฟรชใบสั่งซื้อจากเมนู" →
   ระบบจะสร้างใบสั่งซื้อ **1 ใบต่อวัน** ครอบคลุมทุกช่วงเวลา จัดกลุ่มตามช่วงเวลา → เมนู (ตรงกับใบสั่งซื้อ
   กระดาษจริงของ MEKTEC) เปิดใบที่สร้างมาลองปุ่ม ใช้ค่าระบบ/เพิ่ม/ลด/งดสั่ง/ใช้สต๊อก/เปลี่ยน Vendor/
   เปลี่ยนรอบส่ง/หมายเหตุ ลองเพิ่ม "รายการอื่นๆ" ที่ไม่ผูกกับเมนู แล้วดูประวัติการแก้ไข จากนั้นตรวจสอบ
   ตาราง **"สรุปยอดสั่งซื้อตาม Vendor"** ที่คำนวณให้อัตโนมัติ (จุดนี้แทนขั้นตอนที่เคยต้องไปคำนวณต่อใน
   Excel) สุดท้ายลอง "สร้าง / ดาวน์โหลด PDF"
8. **คู่มือครัวประจำวัน**: เลือกวันที่ที่มีเมนู ดูวัตถุดิบตามจำนวนจริงและ QR Code — สแกนด้วยมือถือ
   (ต้องเป็นมือถือเครื่องที่ล็อกอินระบบนี้ไว้แล้ว) ควรเปิดหน้ารายละเอียดสูตรนั้นทันที
9. **ใบประกาศเมนู**: เลือกสัปดาห์ ลองแก้ไขข้อความในโปสเตอร์ แล้วกด "พิมพ์ / บันทึก PDF"
   (ใช้ฟังก์ชันพิมพ์ของเบราว์เซอร์ เลือกปลายทางเป็น "Save as PDF")
10. **รายงาน**: ลองแต่ละแท็บ (ต้นทุนรายวัน, ต้นทุนต่อเมนู, ยอดซื้อตาม Vendor ฯลฯ) แล้วกด
    Export CSV / PDF / Excel เพื่อยืนยันว่าดาวน์โหลดไฟล์ได้จริง
11. **ผู้ใช้งาน** (ล็อกอินด้วย `admin`): ลองเพิ่ม/แก้ไข/ระงับผู้ใช้งาน แล้วทดสอบเข้าสู่ระบบด้วยสิทธิ์
    Supervisor/Staff/Viewer เพื่อยืนยันว่าปุ่มที่ไม่มีสิทธิ์ถูกซ่อนอย่างถูกต้อง
12. เปิด Google Sheets "MEKTEC Canteen Database" คู่ขนาน เพื่อยืนยันว่าข้อมูลที่กรอกในเว็บถูกบันทึก
    ลงชีตจริง และดูชีต `AuditLogs` เพื่อตรวจสอบประวัติการแก้ไข
13. ทดสอบบนมือถือ/แท็บเล็ตจริงอย่างน้อย 1 เครื่อง (เปิด Web app URL ผ่านเบราว์เซอร์มือถือ)
14. **ตรวจสอบเพิ่มเติมเฉพาะของอัปเดตล่าสุด**:
    - หน้า Login และใบประกาศเมนูควรเห็นโลโก้ MEKTEC จริง (ไม่ใช่ตัวอักษร "M")
    - ในหน้าวางแผนเมนูรายสัปดาห์ ลองพิมพ์แก้ไขในหน้าต่างเพิ่มเมนูแล้วรอสักครู่โดยไม่กดปุ่มบันทึก
      ควรเห็นข้อความ "บันทึกอัตโนมัติแล้ว" ปรากฏ และเมนูควรถูกบันทึกจริงแม้ปิดหน้าต่างทันที
    - ตารางที่มีข้อมูลมากกว่า 10 แถว (เช่น วัตถุดิบ) ควรมีปุ่ม "ก่อนหน้า/ถัดไป" ให้เปลี่ยนหน้า
    - กดปุ่ม "ย้อนกลับ" มุมซ้ายบนหลังสลับหน้าจอไปมา ควรพากลับไปหน้าก่อนหน้าได้ถูกต้อง
    - เปิดใบสั่งซื้อ 1 ใบ ตรวจสอบว่ามีคอลัมน์ "ตามสูตร/ค่าเผื่อ/สต๊อกคงเหลือ/Safety Stock/ส่วนต่าง"
      ครบ แล้วลองกด "ดูตัวอย่างก่อนสร้าง PDF" ก่อนกด "สร้าง / ดาวน์โหลด PDF" จริง — **สิ่งสำคัญ:
      ต้องตรวจสอบเองว่าโลโก้ในไฟล์ PDF ที่ได้แสดงผลถูกตำแหน่งไม่ทับข้อความ** เพราะสภาพแวดล้อมนี้ไม่มี
      Google Apps Script ให้รันทดสอบจริง (ดูข้อ 11 ในหัวข้อถัดไป)
    - ในหน้ารายงาน ลองแท็บ "ต้นทุนรายสัปดาห์" และ "ต้นทุนรายเดือน" และแท็บ "ประวัติราคา" (เลือกวัตถุดิบ
      ที่เพิ่งแก้ไขราคาไปควรเห็นประวัติ)
    - เปิดหน้า Vendor แล้วกด "แก้ไข" Vendor ใดก็ได้ ควรเห็นตารางรายการวัตถุดิบที่ตั้ง Vendor นี้เป็น Vendor ประจำ

หากต้องการอัปเกรดโครงสร้างในอนาคต (เช่น เพิ่มคอลัมน์ใหม่) ให้รันฟังก์ชัน **`upgradeSystem`**
จากตัวแก้ไข Apps Script — ฟังก์ชันนี้จะเพิ่มเฉพาะสิ่งที่ขาด โดยไม่ลบข้อมูลเดิม

## 7. รายการสิ่งที่ควรปรับก่อนใช้งานจริง

1. **เปลี่ยน PIN เริ่มต้นทั้งหมด** และพิจารณาลบ/ปิดใช้งานบัญชีตัวอย่างที่ไม่ใช้จริง
2. **ทบทวนสิทธิ์การเข้าถึง Web App** (`Anyone` vs `Anyone within organization`) ให้เหมาะกับ
   นโยบายความปลอดภัยของบริษัท
3. **ตรวจสอบ/แก้ไขข้อมูลตัวอย่าง** (Vendor, วัตถุดิบ, ราคา, สูตรอาหาร, ล็อตสต๊อก) ให้ตรงกับข้อมูลจริง
   ของโรงอาหารก่อนเริ่มใช้งานจริง — ข้อมูลตัวอย่างมีไว้เพื่อสาธิตการทำงานเท่านั้น
4. **QR Code ใช้บริการภายนอก** (`api.qrserver.com`) หากองค์กรมีนโยบายไม่พึ่งพาบริการภายนอก
   ให้เปลี่ยนไปสร้าง QR ด้วยไลบรารีที่ Host เอง หรือฝัง QR generator ไว้ใน Apps Script โดยตรง
   (แก้ไขจุดสร้าง `qrUrl` ในฟังก์ชัน `renderKitchenToday` ของ `Index.html`)
5. **สำรองข้อมูล (Backup)**: ตั้งค่า Google Drive ให้สำรอง/มีเวอร์ชันของสเปรดชีตอย่างสม่ำเสมอ
6. **Quota ของ Google Apps Script**: บัญชี Google ปกติมี execution time/UrlFetch quota ต่อวันจำกัด
   หากมีผู้ใช้งานพร้อมกันจำนวนมาก (100+ คน) หรือสร้าง PDF บ่อยครั้ง แนะนำใช้บัญชี Google Workspace
   ขององค์กร ซึ่งมี quota สูงกว่าบัญชีส่วนตัวมาก
7. **โลโก้บริษัท**: ใช้โลโก้ MEKTEC จริงแล้วในหน้า Login, ใบประกาศเมนู, และหัวเอกสาร PDF ใบสั่งซื้อ
   (ฝังเป็น Base64 ไว้ในตัวแปร `MEKTEC_LOGO_BASE64` ใน `Code.gs`) — หากต้องการเปลี่ยนโลโก้ในอนาคต
   ให้แทนที่ค่าตัวแปรนี้ด้วย Base64 ของไฟล์ภาพใหม่ (แนะนำใช้เครื่องมือแปลงไฟล์เป็น Base64 แล้ววางทับ)
8. **การขึ้นหน้าใหม่ในไฟล์ PDF**: ใบสั่งซื้อ 1 ใบมีหลายช่วงเวลา ระบบเว้นบรรทัดว่างระหว่างช่วงเวลาเพื่อให้
   มักขึ้นหน้าใหม่โดยอัตโนมัติเมื่อพิมพ์ (Google Sheets ไม่มีคำสั่งบังคับขึ้นหน้าใหม่ตรงจุดที่ต้องการแบบ
   เป๊ะ 100%) — ถ้าช่วงเวลาใดสั้นมากอาจอยู่หน้าเดียวกับช่วงเวลาถัดไป ซึ่งไม่กระทบความถูกต้องของข้อมูล
9. **ทดสอบโหลดจริง**: ทดลองให้ผู้ใช้งานหลายคนกรอกเมนู/สูตรอาหาร/สร้างใบสั่งซื้อพร้อมกันเพื่อตรวจสอบว่า
   LockService ทำงานได้ราบรื่นในสภาพการใช้งานจริงของบริษัท
10. **การอนุมัติใบสั่งซื้อ**: ปัจจุบันมีสถานะ "ร่าง" → "อนุมัติแล้ว" เท่านั้น หากต้องการหลายขั้นตอนอนุมัติ
    (เช่น ตรวจสอบ → อนุมัติ) ให้ขยายฟิลด์ `Status` และฟังก์ชัน `apiApprovePurchaseOrder` เพิ่มเติม
    (มีฟิลด์ "ผู้ตรวจสอบ" แยกจาก "ผู้อนุมัติ" ให้แล้วในหน้าใบสั่งซื้อ)
11. **โลโก้ในไฟล์ PDF**: การแทรกรูปภาพลงชีตชั่วคราวก่อน Export (`sheet.insertImage`) ยังไม่เคยรันทดสอบ
    จริงบน script.google.com — ควรลองสร้าง PDF ใบสั่งซื้อ 1 ใบหลังติดตั้งเพื่อตรวจสอบว่าโลโก้แสดงผลถูกตำแหน่ง
    หากไม่แสดงผล ให้ตรวจสอบว่าได้ Allow สิทธิ์ Google Drive ครบถ้วนตอน Authorize (ดูข้อ 3)

## 8. โครงสร้างไฟล์ในโปรเจกต์นี้

```
Code.gs           ฝั่งเซิร์ฟเวอร์ทั้งหมด (schema, setupSystem, upgradeSystem, API endpoints ทุกโมดูล)
Index.html        หน้าเว็บฝั่งไคลเอนต์ทั้งหมด (HTML+CSS+JS ในไฟล์เดียว)
appsscript.json   Manifest ของโปรเจกต์ Apps Script (เขตเวลา, การตั้งค่า Web App)
README.md         เอกสารนี้
```

ไฟล์เหล่านี้เก็บไว้ใน Git เพื่อควบคุมเวอร์ชัน (version control) เท่านั้น — ตัวระบบจริงทำงานอยู่บน
[script.google.com](https://script.google.com) ไม่ได้รันจาก GitHub โดยตรง หากต้องการ deploy
อัตโนมัติจาก Git สามารถใช้เครื่องมือ [`clasp`](https://github.com/google/clasp) ของ Google ได้ในอนาคต

## 10. โครงสร้างใบสั่งซื้อ (ปรับใหม่ให้ตรงกับเอกสารจริงของ MEKTEC)

เวอร์ชันแรกของระบบสร้างใบสั่งซื้อแยกเป็นคนละใบตาม Vendor ซึ่งไม่ตรงกับวิธีทำงานจริง หลังตรวจสอบ
เอกสารใบสั่งซื้อจริงที่ใช้งานอยู่ (แบบฟอร์ม 02-B) จึงปรับโครงสร้างใหม่ทั้งหมดดังนี้:

- **1 ใบสั่งซื้อ ต่อ 1 วันที่ใช้สินค้า** ครอบคลุมทุกช่วงเวลาในวันนั้น (06:00-08:00, 10:00-13:00 ฯลฯ)
- ภายในใบเดียวกัน **จัดกลุ่มตามช่วงเวลา แล้วจึงจัดกลุ่มย่อยตามเมนู** — วัตถุดิบชนิดเดียวกันที่ใช้ในหลาย
  เมนูจะแสดงแยกเป็นคนละบรรทัดตามเมนูนั้น ๆ (ไม่รวมเป็นยอดเดียวข้ามเมนู) ตรงกับที่พนักงานคุ้นเคย
- คอลัมน์ **สต๊อกคงเหลือ** และ **Safety Stock** แสดงเป็นข้อมูลอ้างอิงเท่านั้น ไม่ได้ถูกหักลบเข้าไปใน
  "จำนวนแนะนำ" โดยอัตโนมัติ — พนักงานยังคงเป็นผู้ตัดสินใจปรับจำนวนสั่งจริงเอง เหมือนที่เคยเขียนปรับ
  ด้วยลายมือบนใบสั่งซื้อกระดาษ (เช่น "10+6" หมายถึงยอดที่ปรับหลังพิจารณาสต๊อก/ความต้องการจริง)
- เพิ่มรายการ **"อื่นๆ"** สำหรับวัตถุดิบที่ไม่ได้ผูกกับเมนูใดเมนูหนึ่ง (เช่น น้ำตาล มะนาว เครื่องปรุงพื้นฐาน
  ที่สั่งเป็นประจำ) ได้อิสระ ไม่ต้องผ่านสูตรอาหาร
- **สรุปยอดสั่งซื้อตาม Vendor** คำนวณให้อัตโนมัติทั้งในหน้าเว็บและในไฟล์ PDF — นี่คือจุดที่ทดแทนขั้นตอน
  เดิมที่ต้องนำใบสั่งซื้อไปแยกคำนวณต่อใน Excel เพื่อสรุปยอดที่ต้องจ่ายแต่ละเจ้า
- PDF มีโลโก้และหัวกระดาษ MEKTEC ซ้ำทุกหน้า, จัดกลุ่มช่วงเวลา → เมนู, มียอดรวมต่อช่วงเวลา, ปิดท้าย
  ด้วยสรุปยอดตาม Vendor และยอดรวมทั้งใบ

**ผลกระทบต่อข้อมูลเดิม:** โครงสร้างชีต `PurchaseOrderItems` เพิ่มคอลัมน์ `TimeSlotID`, `RecipeID`,
`MenuName`, `IsAdhoc` — ถ้าเคยรัน `setupSystem()` มาก่อนเวอร์ชันนี้ ให้รัน **`upgradeSystem()`** อีกครั้ง
เพื่อเพิ่มคอลัมน์ที่ขาด (ใบสั่งซื้อเก่าที่เคยสร้างไว้ก่อนอัปเกรดจะยังอยู่ในชีตแต่ไม่มีข้อมูลกลุ่มช่วงเวลา/เมนู
แนะนำให้สร้างใบสั่งซื้อใหม่แทนใบเก่าหลังอัปเกรด)
